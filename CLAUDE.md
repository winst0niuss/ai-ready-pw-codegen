# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

**AI-Ready PW Codegen** (npm: `ai-ready-pw-codegen`) — an offline Playwright recorder. It runs Playwright's built-in codegen UI and, for every recorded action, captures the target element, selector candidates, accessibility tree, cleaned DOM, screenshot, console logs and XHR/fetch requests. Output is a folder/zip meant to be handed to an AI later for test generation.

## Commands

```bash
npx ts-node src/main.ts <URL> [options]   # run from source (same as npm start -- / npm run record --)
npx ts-node src/main.ts --help            # list CLI flags
npx tsc --noEmit                          # type check
npm test                                  # all unit tests (Vitest, not Jest)
npx vitest run src/__tests__/jsonl-writer.test.ts   # single file
npx vitest run -t "<test name>"                     # single test by name
npm run build                             # compile to dist/
```

CI (`.github/workflows/ci.yml`, Node 20): `npm ci` → `npx tsc --noEmit` → `npm test`.

Release: `bin` → `dist/main.js`, `prepublishOnly` builds. User-visible changes get a separate `chore: bump version to X.Y.Z` commit.

## Architecture

**Flow:** `main.ts` (CLI parse → load Playwright → launch headed Chromium → `Recorder.start()` → `finalize()`) → `recorder.ts` (codegen hooks + per-action capture) → `utils/` (writers, archive, SESSION.md) and `snapshot/` (code that runs in the page).

### Playwright internals — the fragile part

- Actions come from the **internal** `context._enableRecorder(..., { actionAdded, actionUpdated })` API with `recorderMode: 'api'`. It is untyped — accessed via `(context as any)`.
- **Playwright is loaded at runtime** through `utils/playwright-loader.ts`: the `playwright` from the user's cwd project is preferred (so its installed browsers match), falling back to the bundled one. Import `playwright` only as `import type`; never import it for values directly.
- **Version differences** (supported `^1.59.1`, verified on 1.59.1 and 1.63.0):
  - ≤1.62 sends `{ frame, action }`; 1.63+ sends a bare action with iframes embedded in the selector via ` >> internal:control=enter-frame >> `. `utils/codegen-data.ts::normalizeCodegenData` converts both to one shape.
  - Since 1.63 a context holds one recorder app, so the separate Inspector window is skipped (`supportsInspectorWithApi` → `options.inspectorWindow`).

### Per-action pipeline (`recorder.ts`)

- Actions are processed **sequentially** through the `actionQueue` promise chain. Every link has its own `.catch` — without it one failure silently drops all later actions.
- `actionUpdated` (codegen merging keystrokes into one `fill`) **overwrites the last action index** rather than creating a new one; the console progress line is also rewritten in place.
- Iframe actions: `resolveFrame` walks `framePath` to the real `Frame`; target/DOM capture run there, the a11y tree always from `page`. Any failure falls back to `page`.
- Each capture is wrapped in `withTimeout(..., CAPTURE_TIMEOUT_MS)`. Capture failures never block recording — the action is written with an error placeholder and marked yellow in the console.
- Console logs and network responses accumulate between actions and are attached to the **next** processed action.

### Output durability

- `JsonlWriter` appends each line immediately and buffers only the last one so `actionUpdated` can still overwrite it. A crash loses at most one action; an update for an already-flushed line is counted as a "stale update".
- DOM snapshots go to a separate `snapshots.jsonl` to keep `actions.jsonl` small for AI context.
- Shutdown can be triggered by context/page close, browser disconnect, SIGINT, SIGTERM or `--max-actions`; `finalize()` in `main.ts` is guarded by a flag and has a hard 10s timeout (queue drain: 5s).
- With `--har`, the context must be closed before archiving (Playwright flushes HAR only on close).
- The recording dir is deleted after zipping **only** if the archive has bytes and no warnings.

### Docs shipped to users

`docs/DATA_FORMAT.md` and `docs/TEST_GUIDE.md` are copied into every recording (`copyDocsToOutput`, resolved relative to `dist/`/`src/`) and `SESSION.md` is generated by `utils/analysis-prompt.ts`. Changing the output format means updating these docs and `types.ts` together.

## Testing

- Tests live in `src/__tests__/`, default environment `node`. Add `// @vitest-environment jsdom` for in-browser code (e.g. `dom-cleaner.test.ts`).
- Only pure utilities and snapshot helpers are unit-tested. `main.ts`/`recorder.ts` need a live browser — verify recorder changes manually with `npx ts-node src/main.ts <URL>`.
- `snapshot/*` functions are passed to `page.evaluate()` — they must be self-contained (no closures over Node-side imports).
